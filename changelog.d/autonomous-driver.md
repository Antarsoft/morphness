The autonomous module's driver: `bash scripts/auto/run.sh start` checks the brief and budgets, creates the run branch and has the director write the product docs and feature order; `approve` records the owner's one approval; `run` builds the features one at a time, each in its own headless session with `--permission-prompts none` and `--max-budget-usd`, checks every card against the feature's plan and QA result before merging it into the run branch, copies the card's owner items into the version checklist, and redraws `_harness/auto/tracker.md` (a table and a Mermaid flowchart coloured by status). It exits on a feature's tries used up, the run budget, hours, features or a stop request, writes `_harness/auto/exit.md` with what the owner has to do, and `resume` carries on. Waiting features hold their dependants, splits and bug fixes go into the order, and a departure or an owner edit to the docs triggers a re-plan. The live state and session logs stay in the git folder, out of every branch. A stub-`claude` self-test covers 14 scenarios. The guard rules for a run and `/morph-auto` follow.
