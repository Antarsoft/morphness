## What changed

A rule a retro adds ends with `(from <feature-slug>, <YYYY-MM-DD>)`, and a later tightening appends
`; <feature-slug>, <date>`. `bash scripts/prune-counter.sh --prune` lists every tag with the number of
features finished since its date, which the prune's rule audit (step 2) starts from: fewer than three
is `too new to judge`, and the retros after the date are where the problem would have come back.

## Why

Provenance was the feature slug alone, so the prune had to look up when each rule landed before it
could ask whether the problem behind it recurred (the check PR #43 added). The date makes that a
lookup. The tag stays short so it barely moves the rule size gauge.

## How to apply

1. Merge the listed files.
2. Existing `(feature-slug)` tags stay valid. Optionally rewrite them as `(from <slug>, <date>)` with
   the date of that feature's learnings entry or retro, so the prune counts them too.
